# Method sources and local conventions

[Documentation map](README.md) · [Interview method](../skills/ontolog-interview/references/interview-method.md) · [Pilot scenarios](pilot-scenarios.md)

Primary references:

- [Noy and McGuinness, Ontology Development 101](https://protege.stanford.edu/publications/ontology_development/ontology101-noy-mcguinness.html): iterative scope setting, competency questions, classes, properties, and examples.
- [W3C SKOS Primer](https://www.w3.org/TR/skos-primer/): concepts versus labels, concept schemes, broader/narrower/related relations, and mappings across vocabularies.
- [W3C PROV Overview](https://www.w3.org/TR/prov-overview/): attribution and derivation of information.
- [Agent Skills specification](https://agentskills.io/specification): portable skill packaging.
- [OpenAI documentation on skills and MCP](https://developers.openai.com/plugins/concepts/skills): reusable workflow instructions complement live tools.

The interview pacing, structured Markdown schema, lifecycle states, steward decision procedure, metric contract, and Git contribution workflow are this project's proposed operating conventions. They are not requirements of these standards. The records are inspired by SKOS/PROV, not direct serializations of either. Any future standards export must specify mappings and semantic losses.

Use explicit examples, counterexamples, and actual work episodes to elicit meaning. Do not present an existing definition as authoritative before learning a contributor's own account: doing so can conceal disagreement. This is a design choice to evaluate in the pilot, not a claim that interviews alone reveal objective truth.
